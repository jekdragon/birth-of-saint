## TL;DR

Игра **уверенно проходит 44/44 дымовых тестов**, но эти тесты не покрывают рендер — а в `Enemy.draw()` лежит **критический крашевой баг**, который падает на первом же кадре рисования любого врага. То есть фактически игра **не запускается как игру** в текущем виде: menu → start → первый кадр render → `AttributeError`.

Помимо этого найдено несколько **логических багов** (мёртвый код, нереализованные механики, дисбаланс экономики), которые тесты тоже не ловят, потому что тесты проверяют «не падает ли», а не «работает ли как задумано».

## 1. Критические баги (P1)

### 🔴 P1-1: `Enemy.draw()` падает с `AttributeError` — игра не запускается

**Файл:** `enemies.py:174`
**Серьёзность:** 🔴 краш на каждом кадре рендера → игра неработоспособна
**Воспроизведение** (подтверждено напрямую):

```python
>>> e = Enemy('neophyte', 2000, 2000, 1)
>>> e.draw(screen, 1900, 1900, font)
AttributeError: 'Enemy' object has no attribute 'enemy_type'
```

В конструкторе (`enemies.py:110`) атрибут называется `self.type_id`, а в `draw()` (`enemies.py:174`) вызывается `self.enemy_type`:

```python
# enemies.py:110  — конструктор задаёт
self.type_id = type_id

# enemies.py:174  — draw() читает несуществующее
sprite = get_enemy_sprite(self.enemy_type, scale=2)   # ← AttributeError
```

**Почему тесты это пропустили:** в `tests/test_phase25.py` НЕТ ни одного вызова `Game.render()` или `Enemy.draw()`. Все 12 тестов гоняют только `update()`. Smoke-test №1 даже комментирует «15 сек game loop» — но он не рисует.

**Фикс (1 строка):**
```python
sprite = get_enemy_sprite(self.type_id, scale=2)
```

**Рекомендация:** добавить в Phase 2.5 обязательный тестовый шаг «вызвать `Game.render()` хотя бы 1 раз после `start_game`» — без этого smoke-test не гарантирует играбельность.

## 2. Логические баги (P2)

### 🟠 P2-1: Demon не стреляет (мёртвый код в defs)

**Файлы:** `enemies.py:42` (def), `enemies.py:124-126` (init), `enemies.py:146-164` (update)
**Что заявлено:** `COMBAT-SYSTEM.md:108` — «Демон (bat) … Стреляет на расстоянии». В `ENEMY_TYPES["demon"]` есть `shoot_range: 300, shoot_cd: 1.5`. Конструктор создаёт `self.shoot_timer`, но **в `Enemy.update()` нет ни одной строки стрельбы** — demon просто идёт к игроку как неофит.

```python
# проверено: 'shoot'/'fire'/'projectile' не встречаются в Enemy.update()
```

То же касается `cultist` (`shoot_range: 250, shoot_cd: 2.0`) — он тоже не стреляет.

**Фикс:** либо реализовать дистанционную атаку (spawn `Projectile` с `vel` к игроку при `dist < shoot_range` и `shoot_timer >= shoot_cd`), либо удалить поля и поправить `COMBAT-SYSTEM.md`, чтобы не вводить в заблуждение.

### 🟠 P2-2: Ghost «phasing» не реализован

**Файлы:** `enemies.py:69` (def), `obstacles.py` (коллизия)
В `ENEMY_TYPES["ghost"]` стоит `"phasing": True` — призрак должен проходить сквозь препятствия. Но ни `Enemy`, ни игровой цикл это поле **не читают**. Призрак упирается в стены как все. Подтверждено: `hasattr(ghost, 'phasing') == False`.

**Фикс:** в `main.py:183-189` (блок коллизии игрока с препятствиями) это ок (игрок не фазит), но для врагов коллизии со стенами вообще нет — враги сквозь стены проходят и так. То есть фактически «phasing» уже работает для ВСЕХ врагов, потому что коллизия враг→препятствие не реализована нигде. См. P3-1.

### 🟠 P2-3: Формула золота обнуляет экономику для слабых врагов

**Файл:** `main.py:342`
```python
self.player.gold += int(e.score // 10 * self.meta.get_powerup_bonus("greed") * self.player.gold_mult)
```

**Баг:** целочисленное деление `score // 10` даёт 0 для всех врагов с `score < 10` и 1 для `score 10–19`. Проверено для всех обычных типов:

| Враг | score | score//10 | золото за килл (без бонусов) |
|------|-------|-----------|------------------------------|
| neophyte | 10 | 1 | 1 |
| acolyte | 12 | 1 | 1 |
| demon | 15 | 1 | 1 |
| fanatic | 18 | 1 | 1 |
| shade | 14 | 1 | 1 |
| heretic | 28 | 2 | 2 |

Игрок получает **1–2 золота за килл**. При цене powerup «Мощь» = 100–800 это означает **100–800 убийств за один апгрейд**. Достижение `gold_10000` (разблокирует Воскрешение) при таких темпах **практически недостижимо** в рамках 15-минутной сессии. Экономика сломана.

**Фикс (варианты):**
```python
# вариант A — без floor-деления, оставить score/10 как float:
self.player.gold += int(e.score / 10 * self.meta.get_powerup_bonus("greed") * self.player.gold_mult)
# вариант B — использовать xp как меру ценности (он ужеscaled):
self.player.gold += max(1, int(e.score * 0.1 * ...))
```

### 🟠 P2-4: `LevelUpScreen.rerolls_left` не сбрасывается между левелапами

**Файл:** `xp_system.py:69` (init), `xp_system.py:101` (activate)

Это противоречит `COMBAT-SYSTEM.md:146` — «Реролл … лимит 3 за ран» формально соблюдён, но UX-ощущение «запаса» не совпадает с ожиданием «3 на каждый выбор».

**Фикс:** уточнить дизайн (3 за ран vs 3 за выбор) и соответственно либо сбрасывать в `activate`, либо оставить и обновить доку.

### 🟡 P2-6: Whip и melee-оружия не вызывают `on_enemy_killed` → эволюция через melee-килл босса не работает

**Файлы:** `main.py:415` (`on_enemy_killed`), `weapons.py:203` (whip `take_damage`)
В `main.py` коллизия снаряд→враг корректно вызывает `self.on_enemy_killed(e)` (`main.py:282`). Но `WhipWeapon`, `HaloWeapon`, `RosaryWeapon`, `LightningWeapon`, `PrayerWeapon`, `BellWeapon`, `IncenseWeapon` вызывают `e.take_damage(...)` **напрямую** и не сообщают `Game` об убийстве.

Последствия:
- `sound_mgr.play("kill")` не играет для melee-киллов
- `on_enemy_killed` не проверяет эволюцию оружия при убийстве босса melee-оружием (whip — стартовое у Воина!)
- гемы, тем не менее, падят (т.к. dead_enemies цикл в `main.py:336` сканирует `not e.alive`), так что XP идёт.

**Фикс:** либо оружие возвращает список убитых врагов из `update()`, либо `Game` после прохода оружий сканирует «какие враги умерли в этом кадре» и вызывает `on_enemy_killed`. Второе проще:
```python
alive_before = {id(e) for e in self.enemies if e.alive}
for w in self.player.weapons: w.update(...)
for e in self.enemies:
    if id(e) in alive_before and not e.alive:
        self.on_enemy_killed(e)
```

## 3. Логические баги (P3) / долг

### P3-1: Коллизия враг↔препятствие не реализована
В `main.py` есть коллизия игрок↔препятствие (`main.py:183-189`), но враги проходят сквозь все стены и надгробия. На карте «Собор» (узкие коридоры) это убивает тактическую ценность геометрии — мобы просто идут сквозь стены к игроку. Это делает «phasing» ghost (P2-2) избыточным и обесценивает карту.

### P3-2: `spawn_boss` всегда спавнит `antichrist`
`wave_manager.py:108` хардкодит `Enemy("antichrist", ...)`. Босс `pope` (Лжепапа, wave 9+) появляется только как редкий спавн из обычного пула (`wave_manager.py:71`, 5% шанс). Получается два «босса» с разной логикой появления, что запутывает. Стоит unify: либо `spawn_boss` выбирает из `{antichrist, pope}` по волне, либо pope становится элитой.

### P3-3: `incense` / `cross` / `bell` не в `EVOLUTIONS`-проверке тестов
Тест №4 (`test_phase25.py:131`) проверяет только 4 классические эволюции. Новые оружия (`incense`, `cross`, `bell`) имеют записи в `EVOLUTIONS` (`weapons.py:117-119`), но их эволюции не протестированы. При этом `can_evolve` требует `self.level < 8` вернуть False — то есть уровень 8 обязателен. Стоит добавить в тест.

### P3-4: `music_mgr` создаётся, но не сохраняется — сборщик может убрать
`main.py:60-63`:
```python
from music import MusicManager
music_mgr = MusicManager()   # ← локальная переменная, не сохраняется
music_mgr.init()
```
`music_mgr` — локальная переменная в `init_sounds()`. После выхода из функции ссылка теряется, объект становится кандидатом на GC. На практике pygame.mixer.music держит поток, так что музыка может играть, но `stop()` уже не вызвать. Сохранить как `global` или атрибут `Game`.

### P3-5: Тач-управление читает события внутри `handle_input`, но `handle_events` уже забрал очередь
`player.py:232`:
```python
for event in pygame.event.get([pygame.FINGERDOWN, pygame.FINGERUP, pygame.FINGERMOTION]):
```
В `main.py` `handle_events()` уже делает `pygame.event.get()` без фильтра (`main.py:135`), вытягивая ВСЕ события из очереди. К моменту вызова `player.handle_input()` очередь touch-событий **уже пуста** — тач-управление на текущий момент **не работает**. Нужен единый poll событий с последующей диспетчеризацией, либо пулить с фильтром в обоих местах осторожнее.

### P3-6: `not hasattr(self, '_reaper_spawned')` уже исправлено, но паттерн уязвим
`main.py:86` и `main.py:105` корректно инициализируют `self._reaper_spawned = False` в `__init__` и `start_game`. Это зафиксировано в `lessons.md`. Хорошо. Но аналогичный паттерн `e._gem_dropped` в `main.py:338` (`hasattr(e, '_gem_dropped')`) — тот же риск: если враг создан без инициализации, флаг проставится. Сейчас работает, но хрупко.

## 5. Производительность

### Тест №2 (stress, 300 врагов) проходит: FPS ≥ 30 на стенде.
Но это **десктоп (i-class CPU)**. В браузере через WASM (pygbag) производительность PyGame в 3–5× ниже. Риски:

### ⚡ P3-perf-1: Квадратичные коллизии без spatial index
- `main.py:261-299` — для каждого снаряда цикл по всем врагам
- `weapons.py:188` (whip), `288` (halo), `414` (prayer) — каждое оружие каждый кадр сканирует всех врагов
- При 300 врагах × ~10 снарядов × 6 оружий = ~18000 проверок/кадр

**Рекомендация:** spatial hash grid (`dict[(int,int)] -> list[Enemy]`) с размером ячейки ~100px. Вставка O(n), запрос O(k) вместо O(n). Это стандарт для survivor-like и прямо упомянуто в ROADMAP.md:155 (Top Risk №2).

### ⚡ P3-perf-2: `enemy.draw()` создаёт `sprite.copy()` при каждом hit_flash
`enemies.py:177`:
```python
if self.hit_flash > 0:
    sprite = sprite.copy()           # ← аллокация Surface каждый кадр
    sprite.fill((255,255,255), special_flags=pygame.BLEND_ADD)
```
При 300 врагах под AoE это 300 аллокаций/кадр. Кешировать «белую» версию спрайта или использовать `BLEND_ADD` через временный overlay без copy.

### ⚡ P3-perf-3: `ScreenFlash.draw()` создаёт `pygame.Surface(WIDTH, HEIGHT)` каждый кадр флэша
`effects.py:49` — full-screen SRCALPHA surface размером 1024×768. На частых hit'ах это дорого. Сделать один постоянный overlay-surface и менять только alpha.

## 6. Тестовое покрытие

### 🟠 T-1 (P2): Тесты не вызывают `render()` / `draw()`
Как следствие — P1-1 (краш `Enemy.draw`) прошёл незамеченным. Smoke test должен покрывать весь конвейер `handle_events → update → render`, а не только `update`.

**Минимальный патч тестов:**
```python
# после g.update(...) добавить:
try:
    g.render()
    check("render() no crash", True)
except Exception as e:
    check("render() no crash", False, str(e))
pygame.display.flip()
```

### T-2 (P3): Нет тестов на новые подсистемы (arcana, relics, cathedral, leaderboard, save)
Phase 3 добавил 5 новых систем, но `test_phase25.py` их не покрывает. Есть базовые тесты arcana-логики через `Game.start_game` (неявно), но:
- `leaderboard.add_score` / `get_entries` не тестируется (включая edge-case: пустой список, >20 записей)
- `save_progress` / `load_progress` не тестируется (round-trip)
- `cathedral.generate_cathedral` коллизии не тестируются
- `RelicManager.spawn_relic` / подбор реликвии не тестируется

### T-3 (P3): Нет assertion на дисбаланс экономики
Тест №8 проверяет покупку powerup, но не проверяет, **сколько времени** занимает накопление на него. Граничный тест «за 15-минутную сессию игрок может купить хотя бы 1 powerup» поймал бы P2-3.

## 7. Безопасность / корректность данных

1. **`save_system.py`** — нет валидации загружаемого JSON. Если файл повреждён/подменён, `meta.powerups` может содержать произвольные ключи, `unlocked_chars` — несуществующие персонажи. `load_progress` ловит `Exception` и печатает ошибку, но оставляет `meta` в частично-загруженном состоянии. Стоит валидировать ключи против `POWERUP_DEFS` / `CHARACTERS`.
2. **`leaderboard.py`** — `add_score` доверяет всем полям; нет sanitize `character` (может быть любой строкой из сохранёнки). Не критично для single-player, но при будущей синхронизации стоит ограничить.
3. **`music.generate_ambient_wav`** пишет WAV в `assets/sounds/` при первом запуске. Если каталог read-only (например, install dir), упадёт молча (поймано `try/except` в `MusicManager.init`). ОК, но стоит логировать.

## 8. Стиль и консистентность (мелочи)

- `enemies.py:7` импортирует `WHITE, RED, DARK_RED, YELLOW, PURPLE, ICE_BLUE, GOLD` — `WHITE` и `GOLD` не используются в файле. Мертвый импорт.
